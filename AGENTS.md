# REN marketplace-bot — рабочие правила

Проект: бот и скрипты синхронизации каталога цветочной студии REN
(Flowwow, Яндекс Маркет, Яндекс Еда, Яндекс Бизнес, Tilda, МойСклад).

## Критичные правила записи в Flowwow (инцидент 25–26.11.2026)

**Что случилось.** Массовое обновление 130 карточек через классический API
`products/update` перезаписало составы: у всех позиций количество стало 1 шт.
12 авторских букетов при этом родились с единицами ещё при создании через бота.
Восстановлено по снимку `fw_details.json` (118 шт) и по Google-таблице,
лист «Букеты», колонка «Состав букета» (12 шт).

**Первопричина (три слоя):**

1. API Flowwow сохраняет количество в `consist` ТОЛЬКО из ключа `val`.
   Ключи `quantity`, `qty`, `count`, `amount`, `value` игнорируются МОЛЧА —
   запрос принимается, `summary.success = true`, а в карточке записывается 1 шт.
2. Формат чтения ≠ формат записи: MCP `get_product_details` отдаёт состав
   с ключом `quantity`, и этот же ключ по ошибке использовался на запись.
3. Не было контрольного чтения: успешный ответ API был принят за успешную
   запись. Порча обнаружилась только глазами владелицы в кабинете.

**Правила, обязательные к исполнению:**

- Состав (`consist`) писать с ключом `val` (плюс `quantity` для читаемости).
  См. `flowwow_api.py` — нормализация делается там, не удалять.
- Ответ `success` от API Flowwow НЕ означает, что данные сохранились верно.
  Неизвестные ключи игнорируются без ошибок.
- Любая массовая запись — только в таком порядке:
  1. снимок текущего состояния в файл (образец — `fw_details.json`);
  2. запись ОДНОГО товара;
  3. чтение обратно (`get_product_details`) и сверка полей;
  4. только потом пачка, с прогресс-файлом;
  5. после пачки — выборочная сверка 2–3 карточек.
- Новое поле/новый формат на записи — сначала тест на одном товаре
  с чтением результата.
- Источники истины для составов с количествами:
  Google-таблица (лист «Букеты», «Состав букета», из заказов МойСклада) —
  главный; снимки `fw_details.json` — резерв. Названия и описания карточек
  количеств НЕ содержат.

Эти же правила продублированы в Google-таблице на листе «Правила»
(разделы `flowwow` и `контроль`) — их читает бот через `rules_sheet.py`.

## Прочие правила владелицы

- Сначала спросить, потом делать. Никаких массовых правок без согласования.
- Топ-18 Flowwow не редактировать — только уведомления в бота, правит флорист.
- «Аквабокс», «бесплатно», «скидка», «подарок» — нигде в текстах.
- Состав в табах Tilda не указывать (сезонная подмена цветов).
- Цены: Тильда ×1.1, Еда ×1.3, Маркет ×1.5 от base = fw/1.5 − 150,
  округление до десятков.
- 5 выключенных растений (Стефанотис, Монстера 100 см, Непентес, Сингониум,
  Фикус) на Tilda не загружать.

## Растения (добавлено 26.11)

Категория «Растения» в боте (кнопка «🪴 Растения», артикулы REN-P, лист «Растения»).
Подпись флориста: `Название / Цена / Высота*ДиаметрГоршка [/ Штук]`.

- Flowwow: sub 14. У неё ДРУГАЯ схема (fw_subcat14_props.json): поля consist НЕТ
  (не отправлять!), наличие — stock (не productionTime), обязателен
  wateringFrequency, свои thematicSelections (1,32,33,34,40,48,53,159).
- Цена Flowwow: (base+150)×1.4 — наценка 40% (решение владелицы), остальные
  площадки как у букетов.
- Маркет: категория 61454449 «Растения комнатные», схема market_plant_params.json,
  справочник видов (275) — market_plant_names.json. ТН ВЭД: 0602909100 цветущие,
  0602909500 прочие.
- Еда: категория «Комнатные растения» (создаётся импортом), состав — ближайший
  компонент справочника.
- Tilda: рубрика «Растения» автоматически, вопросы про цвет не задаются.
- Первый запуск — строго по правилам контроля: одно растение, чтение карточки
  обратно, сверка, потом остальные.
